# Clear between jobs

**The highest-impact lesson in this tutorial costs nothing to run.**
When you finish one job and start a different one, run `/clear`.

Staying in the same thread because it is convenient is typically very expensive.
That finished conversation is not sitting quietly out of the way — it is being resent on every
message until the session ends. A session sitting at 80,000 tokens of history
drops to nothing the moment you clear.

**Rename before you clear.** Run `/rename` inside the session first, and
`/resume` can find it again by name if it turns out you needed it after all. You
are not throwing the work away. You are stopping the next job from carrying it.

**Do not clear here.** Clearing is how this tutorial ends — it is the last thing
you will be asked to do — and doing it now would take the tutorial with it. If
you want to try it immediately, open a second window and try it there.

## Takeaways

- Finished one job and starting another? **`/clear`.**
- An old conversation isn't sitting quietly; it is resent on every message until the session ends.
- **`/rename` first**, so `/resume` can find it if you were wrong.
- Running `/clear` as a habit is going to cut token usage far more than any other strategy in this tutorial
